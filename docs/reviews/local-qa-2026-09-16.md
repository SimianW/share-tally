## Finding: remote HTTP cannot create bills

Reproduction in T3 Code Preview:

1. Open `http://dev-2a1m:5188`, enter the test identity, create a group, and open New bill.
2. Enter a title, total `10.00`, and own share `9.95`.
3. Submit. The form displays `crypto.randomUUID is not a function` and creates no bill.

Direct browser inspection shows `isSecureContext === false`, `typeof crypto.randomUUID === 'undefined'`, and `typeof navigator.clipboard === 'undefined'`. On `http://127.0.0.1:5188`, the same checks return `true`, `'function'`, and `'object'`; submitting the same bill succeeds.

Affected source: `client/src/play/Bills.tsx:223`. Repayment recording also directly calls this API at `client/src/play/Repayments.tsx:82`, so it has the same dependency; its remote-HTTP submit was not separately exercised. Invitation copying handles the missing clipboard API with “Select the link below and copy it manually.”

Impact: blocks financial creation through remote plain HTTP, including this preview address. Use HTTPS for deployed and remote testing, or separately implement support for insecure local development. No workaround or production-code fix was applied during this acceptance run. Localhost passing does not verify the actual HTTPS deployment.
