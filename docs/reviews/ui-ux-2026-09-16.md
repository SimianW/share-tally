# UI and navigation changes for #20 and #23

Returning to a visited group or Overview now displays its cached data while fetching a current server snapshot. Group navigation preserves the sidebar. New bill and Members & invites share the group heading's action area, with buttons that wrap on mobile and have at least 44 px tap targets. Member balances and repayment suggestions use short helper text.

#23 takes precedence over #20's earlier proposal to show a background stale-data notice in the group workspace. Group connection and read failures retain visible data and recover silently. Initial failures show “Couldn't load this group.” and Try again. Access failures remove protected content. Mutation and conflict messages remain visible. Overview refresh errors retain balances and offer Retry balances.

## Cache and synchronization

- TanStack Query stores `/groups`, `/groups/:id`, `/groups/:id/bills`, and `/summary` as separate query keys. Sidebar balances and the selected panel subscribe to the same bill/ledger response. Financial effects are never calculated in the client.
- Each signed-in user gets a separate QueryClient, mounted with the Clerk user ID as its key. Unmounting clears it and cancels outstanding reads. Nothing is persisted to browser storage by this cache.
- Data is immediately stale for revalidation purposes. Unobserved queries are collected after five minutes. Reads are deduplicated per key and time out after 15 seconds. Shared reads may complete after navigation so another observer can reuse them; navigation does not abort another component's request.
- Read subscriptions do not independently fetch. Entry effects and the existing SSE controller own refresh timing, so the active group still reads after stream readiness. Mutations cancel obsolete reads, invalidate cached group resources and summaries, then refetch them from the server.
- SSE changes cancel in-flight group snapshots. Its existing dirty/read loop and reconnect path recover from cancellation and fetch current state. Query cancellation prevents an obsolete response from committing to the cache. Normal focus, visibility, and online recovery no longer announce a failure before attempting a connection.
- 401 responses clear protected cached values. Group 403/404 responses clear that group's resources, remove its cached membership entry when present, and discard an affected aggregate summary. Authentication and access errors remain actionable.
- Group-specific forms remain keyed by group ID even though the workspace itself no longer remounts on each group selection.

## Validation

`pnpm --dir client build`, `pnpm --dir client lint`, `pnpm --dir client test:groups`, and `pnpm --dir client test:avatar` pass.

The group smoke test uses the real UI, Express and isolated PostgreSQL with test-only identities. It now calls `scripts/smoke-navigation.mjs`, which holds network responses until assertions finish. Coverage includes:

- A → B → A and group → Overview without loading-content replacement.
- Preserved sidebar DOM and cached balances; one concurrent request for the shared group resource.
- Delayed focus, visibility and online revalidation with a MutationObserver checking for transient warning text, not just its eventual disappearance.
- Delayed A responses after switching to B, with B's identity and values preserved.
- First-visit skeleton height and absence of another group's financial values.
- Background 503 failure and automatic recovery without the connection alert, initial-load failure with retry, and revoked access hiding balances.
- Account change without document reload while the new user's requests are held, plus sign-out/sign-in isolation.

Existing smoke coverage continues to check bill/share/repayment mutations, authoritative balances, response-loss retries, retained drafts, SSE recovery, permissions, attention actions and account isolation. Google authentication and production deployment were not re-tested in this UI change.

## Selected design: A

The owner selected prototype A, “Balance first”. The production workspace now places the balance and next suggested transfer side by side, followed by shared purchases. Full member balances, all transfer suggestions and repayment history remain below. The highlighted transfer prefers the current user's incoming/outgoing suggestion and uses the server's amount; the zero-balance state is explicit. View repayments scrolls to and focuses the existing repayment section. Real creation, invitation and repayment controls remain connected.

The three original variations, demo runner and their application context are preserved on local branch `prototype/group-workspace-abc`, commit `9d34ffe5d4b2acf488e2e992860c008421afc148`. The selected design was rewritten into production components; the prototype files, variant parameter and switcher were removed from the working implementation. To revisit the study, check out that branch in a separate worktree, install client dependencies and run `pnpm --dir client prototype`.

## Post-review membership refresh fix

A browser regression confirmed that successful group creation followed by a failed `/groups` refresh omitted the new group from navigation. The existing error/retry UI was visible, so the failure was not silent. Creation and joining now cancel obsolete list reads and upsert the returned group by ID before revalidation. A transient failure retains the successful membership; authorization failures still evict protected data. The browser smoke covers create, join, repeated join without duplicates, and successful retry after a forced 503.
